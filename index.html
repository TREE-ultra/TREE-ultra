02 / 关于

写代码的时候在想什么

我做的东西大多从一个"如果能拖就好了"的想法开始。圆锥曲线在课本上是一张静态插图， 但一旦能亲手拖动切面、看着它从圆变成椭圆再变成双曲线，那条抽象的定义就变成了直觉。 圣诞树也一样——参数表是死的，绕着它转一圈、看清每个器材身上那点细节，它才活过来。

另一个方向是反向的趣味。丑网站那个项目技术含量近乎为零，但"全站零圆角"这条规则一旦立起来， 整个网页设计就变成了一场很具体的挑战：怎么让一个表单既能用、又足够让人难受。这比堆特效有意思得多。

所以我的技术栈一直很克制。三个作品没有一个用了构建工具，全部是单页或单文件， 丢到任何地方都能打开。我更愿意把时间花在交互的细节和数据的准确性上—— 圣诞树里二十一件器材的重量、像场圆、传感器尺寸，都逐条对着厂商官方规格页核过， 还写了份研究笔记记录来源。

  • 前端原生 HTML / CSS / JS，无构建
  • 图形Canvas 2D · Three.js
  • 方向交互可视化、科普、数学直觉
  • 习惯单文件优先，零外部依赖
  • 数据规格以厂商官方页为准，逐项交叉核验
  • 侧写摄影器材爱好者，参数控
03 / 创作方式

这些作品都源自 DeepSeek

上面三个仓库里的每一个项目，最初的构想、算法推导和代码实现，都由 DeepSeek 协助完成。我负责提出想法、追问细节、验证结果。

由 DeepSeek 协助构建

说得更直白一点：这些项目不是我一行一行敲出来的。是 DeepSeek 帮我把一个模糊的念头 变成了能跑的东西——圆锥曲线怎么用 Canvas 画、离心力怎么模拟、丑网站那十五个页面 怎么共用一套外壳。

它负责把想法翻译成代码，我负责判断哪个方向值得做、结果对不对、以及好不好玩。 圆锥喵的退化情形是追问出来的，Camera Tree 的参数表是逐条逼问厂商规格页核对出来的， 丑网站的规则能一路贯彻到第十五个页面，是因为反复推翻重来。

  • 构想DeepSeek 提议技术方案与实现路径，我选定主题并定义边界
  • 推导解析几何与物理直觉部分由 DeepSeek 推导，再逐条复核
  • 代码主体实现与调试由 DeepSeek 生成，我持续追问直到跑对
  • 核验器材规格以厂商官方页为准，DeepSeek 协助整理成结构化数据
  • 验收最终交互与视觉由我把关，DeepSeek 按反馈持续迭代
